# Remote Duel 无域名公网部署路线

状态：首版采用  
决策日期：2026-08-09  
适用范围：熟人之间、小规模、受控的异地对战测试

## 1. 路线结论

首版不申请域名，不配置 DNS，不申请 TLS 证书，也不要求 Caddy。两台 Windows 客户端直接连接阿里云 ECS 的公网 IPv4 地址：

```text
Windows Client A ─┐
                  ├─ ws://ECS_PUBLIC_IP:8765 ─> Authoritative Spells Server
Windows Client B ─┘
```

服务器仍然是唯一权威节点，负责房间、身份、战斗规则、快照和事件分发。它不是简单的消息转发器。摄像头、CV、渲染和声音仍只在客户端运行，因此改用公网 IP 不会改变战斗架构和玩法逻辑。

## 2. 为什么不需要域名

WebSocket 可以直接使用 IPv4 地址。域名的作用主要是提供易记地址，并方便自动签发可信 TLS 证书；它不是服务器接受和分发消息的必要条件。

首版地址示例：

```text
ws://47.100.20.30:8765
http://47.100.20.30:8765/health
```

ECS 公网 IP 应尽量使用固定公网 IPv4 或绑定弹性公网 IP，避免实例重启或重建后地址变化。客户端地址通过 `SPELLS_SERVER_URL` 配置，不写死在代码中。

## 3. 部署组成

- 一台带公网 IPv4 的阿里云 Linux ECS；
- 一个无摄像头、无 GUI 依赖的 Python 权威服务；
- Docker Engine 与 Docker Compose Plugin（推荐）；
- 阿里云安全组开放 `8765/TCP`；
- 管理用 `22/TCP` 仅允许管理员当前公网 IP；
- 两台安装完整客户端的 Windows 设备。

默认 `compose.yaml` 只启动 `spells-server`，并映射 `8765:8765`。`compose.tls.yaml` 和 Caddyfile 只作为将来升级域名与 `wss://` 的可选配置，不得阻塞首版上线。

## 4. 分阶段实施

### 阶段 A：仓库内验证

1. 完整测试通过；
2. 本机启动服务端和两个探针客户端；
3. 验证建房、加入、ready、施法、胜负、重连和 rematch；
4. 确认服务端不加载 OpenCV、MediaPipe、Pygame 或显示设备依赖。

### 阶段 B：ECS 公网 IP 部署

1. 创建或使用已有 Linux ECS，确认公网 IPv4；
2. 安装 Docker 与 Compose；
3. 安全组开放 `8765/TCP`：优先只允许两位玩家的公网 IP；测试网络地址不固定时，可在短期验收窗口开放 `0.0.0.0/0`，完成后收紧；
4. 上传或拉取仓库，执行 `docker compose up -d --build`；
5. 在 ECS 本机检查 `http://127.0.0.1:8765/health`；
6. 在外部设备检查 `http://ECS_PUBLIC_IP:8765/health`；
7. 运行公网自动探针。

### 阶段 C：两台真实设备验收

两台设备使用不同网络，例如家庭宽带和手机热点，并配置：

```powershell
$env:SPELLS_SERVER_URL = "ws://ECS_PUBLIC_IP:8765"
python main.py
```

完成房间码加入、角色选择、键盘/CV 混用、完整胜负、断线恢复和连续三局 rematch。验收结果记录到 `docs/remote_duel_progress.md`。

### 阶段 D：运行加固

- 保留现有连接数、消息大小、消息速率和施法速率限制；
- 使用 Docker 自动重启、健康检查和日志轮转；
- 只保留必要安全组端口；
- 不在日志中输出完整重连令牌；
- 部署更新前确认没有正在进行的房间；
- 定期安装 ECS 系统安全更新。

### 阶段 E：可选 TLS 升级

以后若决定公开运营、加入账户/聊天/支付，或需要在不可信网络中降低窃听和篡改风险，再申请域名并切换到：

```text
wss://duel.example.com
```

升级只替换连接入口和 Compose 配置，不改游戏协议、房间逻辑或战斗引擎。

## 5. 明确的安全边界

`ws://` 是明文连接。链路上的网络运营者、恶意热点或中间人理论上可以看到或篡改游戏命令、房间码和重连信息。当前系统不传视频、图像、语音、账户、聊天或支付信息，因此首版可在用户明确接受后用于受控测试，但仍不能视为安全的公开互联网服务。

以下任一情况出现时，应把 `wss://` 升级列为发布前置条件：

- 面向陌生用户公开服务；
- 传输账户、聊天、个人资料或付费信息；
- 需要稳定品牌地址；
- 需要浏览器 HTTPS 页面直接连接 WebSocket；
- 安全审计要求全链路加密。

## 6. 回退方案

- 部署失败：切回上一已验证 Git commit 并重新构建容器；
- 新版本异常：停止接收新房间，等待当前房间结束后回退；
- 公网暴露风险过高：立即从安全组移除 `8765/TCP`，服务端可继续在本机验证；
- 公网 IP 变化：只更新客户端 `SPELLS_SERVER_URL`，无需修改代码；
- 以后切换 TLS：使用 `compose.tls.yaml`，默认直连配置仍可用于故障诊断。

## 7. 完成标准

- ECS 公网 IP 的 `/health` 可从外网访问；
- 自动公网探针完成完整对局；
- 两台异地设备通过 `ws://ECS_PUBLIC_IP:8765` 和房间码完成连续三局；
- 双方权威状态一致，断线和非法输入有明确处理；
- 离线模式仍可在服务关闭时正常运行；
- 部署、更新、回退和安全边界均有文档记录。
