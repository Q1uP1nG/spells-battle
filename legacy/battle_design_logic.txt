Spells 双人对战系统设计逻辑
================================

项目目标
--------
把 Spells 从单人“识别动作 -> 播放特效”的 demo，升级成一个实时双人摄像头对战系统。

核心闭环：

Webcam 输入
-> 屏幕中线分区
-> 左右两名玩家分别识别手/魔杖轨迹
-> 咒语分类
-> 生成弹道、护盾、回血或控制效果
-> 特效移动与碰撞检测
-> 修改 HP / Mana / 状态
-> 一方 HP 归零后结束对战


整体模式
--------
程序启动后先进入入场页面，而不是直接进入对战。

1. Solo Spell Showcase / 单人术法展示
   用于展示和练习五个咒语的识别与特效。
   玩家只控制 P1，右侧 P2 作为训练假人。
   这个模式适合课堂展示 CV 识别、轨迹可视化和每个咒语的视觉效果。

2. Duel Battle Mode / 双人对战
   左右两名玩家同时施法。
   使用 HP、Mana、全局冷却、单咒语冷却、护盾、弹道碰撞和胜负结算。

M 键可以从任意模式回到主菜单。


屏幕与玩家区域
--------------
1. 摄像头画面中间画一条竖线。
2. 左半屏为 Player 1，右半屏为 Player 2。
3. 每个玩家只识别自己半屏内的手部和杖尖轨迹。
4. 每个玩家的咒语从自己的杖尖位置或身体附近生成，默认向对方半屏飞行。
5. 若手或杖越过中线，优先按手腕位置归属玩家；MVP 版本可直接忽略越界轨迹。


玩家基础属性
------------
每个玩家初始状态：

HP: 100
Mana: 100
Mana 每秒恢复: 12
护盾值: 0
护盾持续时间: 0
胜利条件: 对方 HP <= 0

HP 不超过 100。
Mana 不超过 100。
Mana 是蓝条 / 魔力条，是施放所有咒语都会消耗的资源；它不是护盾条。
护盾值是 Protego 单独生成的临时防御值，界面中用 SH 单独显示。
HP 归零后停止识别该玩家施法，并显示胜利提示。


为什么需要冷却期
----------------
必须设置冷却，否则会出现两个问题：

1. 游戏性问题：
   玩家连续挥动时会不断生成咒语，变成无脑弹幕。

2. CV 识别问题：
   同一个动作可能在多帧内被重复分类，如果没有冷却，一个手势会被判定成多次施法。

所以系统需要三层限制：

1. 全局施法冷却 global_cast_cooldown
2. 单咒语冷却 spell_cooldown
3. 轨迹消费机制 trajectory_consumed


冷却与施法规则
--------------
每个玩家拥有独立冷却状态。

全局施法冷却：
玩家成功施放任意咒语后，进入 2.3 秒全局冷却。
全局冷却期间，该玩家不能释放任何新咒语。

单咒语冷却：
每个咒语有自己的冷却时间，避免重复刷同一技能。

轨迹消费机制：
一段轨迹一旦成功识别并施法，立刻标记为 consumed，并清空轨迹缓冲区。
只有当玩家回到 IDLE / READY 状态后，才允许记录下一段新轨迹。

施法成功必须同时满足：

1. 玩家没有死亡
2. 玩家不在全局冷却中
3. 玩家不在沉默 / 眩晕状态中
4. 该咒语自己的冷却已经结束
5. Mana 足够
6. 轨迹长度达到要求
7. 分类置信度达到阈值
8. 当前轨迹没有被 consumed


咒语体系
--------
建议期末版本使用 5 个核心咒语：

1. Incendio 火焰咒
2. Stupefy 昏击咒
3. Glacius 冰冻咒
4. Protego 守卫咒 / 护盾
5. Lumos 荧光咒 / 回血


咒语参数
--------
Incendio
- 类型: 攻击
- 动作: 快速前刺
- Mana 消耗: 25
- 单咒语冷却: 3.0 秒
- 伤害: 22
- 弹道速度: 快
- 弹道半径: 28 px
- 特效: 火球 / 火焰粒子喷射
- 定位: 高伤害压制，专门惩罚回血

Stupefy
- 类型: 攻击 + 打断
- 动作: 闪电折线
- Mana 消耗: 35
- 单咒语冷却: 5.0 秒
- 伤害: 16
- 弹道速度: 中等
- 弹道半径: 22 px
- 命中效果: 对方 1.0 秒不能施法
- 特效: 红色冲击光束
- 定位: 打断 Lumos 或复杂施法

Glacius
- 类型: 控制
- 动作: 向下冰冻斩
- Mana 消耗: 30
- 单咒语冷却: 4.6 秒
- 伤害: 10
- 弹道速度: 慢
- 弹道半径: 34 px
- 命中效果: 对方进入 frozen 状态 2 秒，并小幅延长对方全局冷却
- 特效: 蓝色冰波 / 局部结冰滤镜
- 定位: 克制火球、削弱护盾、拖慢对方施法节奏

Protego
- 类型: 防御
- 动作: 大 U 形 / 大弧线
- Mana 消耗: 30
- 单咒语冷却: 6.0 秒
- 护盾值: 35
- 持续时间: 3 秒
- 特效: 玩家前方半透明护盾弧
- 定位: 抵挡攻击，但会被 Glacius 克制

Lumos
- 类型: 回复
- 动作: 向上轻挑
- Mana 消耗: 40
- 单咒语冷却: 8.0 秒
- 回复量: 18 HP
- 引导时间: 1.2 秒
- 特效: 杖尖光晕 / 玩家周围柔光
- 定位: 低血量续航，但容易被打断


推荐冷却表
----------
全局施法冷却: 2.3 秒

Incendio: 3.0 秒
Stupefy: 5.0 秒
Glacius: 4.6 秒
Protego: 6.0 秒
Lumos: 8.0 秒

这样设计的原因：

1. Incendio 是基础攻击，所以仍然最短，但 3 秒间隔可以避免火球连发。
2. Stupefy 有打断能力，所以冷却更长，防止一直沉默对方。
3. Glacius 有灭火、削盾和控节奏作用，冷却中等偏长。
4. Protego 可以挡伤害，不能太频繁，否则会变成一直龟缩。
5. Lumos 能回血，必须最贵且冷却最长，避免残血玩家无限续命。


克制关系
--------
整体关系：

Incendio 克制 Stupefy / Lumos
Protego 克制 Incendio / Stupefy
Glacius 克制 Incendio / Protego
Stupefy 克制 Glacius / Lumos
Lumos 克制消耗战

具体规则：

1. Incendio vs Lumos
   Lumos 引导期间，如果被 Incendio 命中，回血取消，并额外受到 6 点伤害。

2. Protego vs Incendio
   Incendio 命中护盾时，优先扣护盾值。
   护盾值足够时，玩家不受伤害。

3. Protego vs Stupefy
   护盾可以抵挡 Stupefy 的伤害和沉默效果。
   Stupefy 命中护盾时，护盾扣 20。

4. Glacius vs Protego
   Glacius 命中护盾时，护盾值减少 20，并让护盾剩余持续时间减少 1.5 秒。
   如果护盾值被削到 0，护盾立刻消失。

5. Stupefy vs Lumos
   Lumos 引导期间，如果被 Stupefy 命中，回血取消，对方进入 1.0 秒沉默。

6. Stupefy vs Glacius
   Stupefy 可以打断正在施法的 Glacius。
   若双方弹道碰撞，则 Stupefy 穿透但伤害减半、速度降低。

7. 三攻击咒语弹道循环克制
   Glacius 克制 Incendio：冰球碰到火球时，火球消失，冰球继续飞行但略微削弱。
   Incendio 克制 Stupefy：火球碰到闪电时，闪电消失，火球继续飞行但略微削弱。
   Stupefy 克制 Glacius：闪电碰到冰球时，冰球消失，闪电继续飞行但略微削弱。


弹道与碰撞
----------
攻击咒语会生成 projectile 对象。

projectile 需要记录：

owner: 玩家编号
spell: 咒语名称
position: 当前坐标
velocity: 移动速度
radius: 碰撞半径
damage: 伤害
remaining_lifetime: 剩余存活时间
status_effect: 附加状态

每帧更新：

1. 更新 projectile 位置。
2. 检查 projectile 是否越界。
3. 检查 projectile 是否撞到对方护盾。
4. 检查 projectile 是否撞到对方玩家区域 / 身体框。
5. 检查两个 projectile 是否互相碰撞。
6. 命中或抵消后播放特效，并删除 projectile。


攻击咒语碰撞表
--------------
Incendio vs Incendio:
双方抵消，生成火花爆炸。

Stupefy vs Stupefy:
双方抵消，生成红色冲击波。

Glacius vs Glacius:
双方抵消，生成短暂冰雾。

Incendio vs Stupefy:
Stupefy 消失。
Incendio 继续飞行，但伤害和半径略微降低。

Incendio vs Glacius:
Incendio 消失。
Glacius 继续飞行，但伤害和速度略微降低，生成蒸汽特效。

Stupefy vs Glacius:
Stupefy 穿透继续飞行，但速度和伤害略微降低。
Glacius 消失。


回血逻辑
--------
Lumos 不是瞬间回血，而是引导回血。

释放 Lumos 后：

1. 玩家进入 healing 状态。
2. 播放 1.2 秒光晕引导特效。
3. 如果期间没有被 Incendio 或 Stupefy 命中，则回复 18 HP。
4. 如果被命中，则回血取消。
5. HP 最高只能回复到 100。

这样可以避免玩家残血时无限瞬间回血。


护盾逻辑
--------
Protego 释放后：

1. 玩家前方生成护盾弧。
2. 护盾值为 35。
3. 最多持续 3 秒。
4. 攻击命中护盾时优先扣护盾值。
5. 护盾值 <= 0 或持续时间结束后消失。
6. Glacius 对护盾有额外削弱效果。

护盾只挡来自正面的 projectile。
MVP 版本可以简化为：只要护盾存在，就挡所有来自对方的 projectile。


状态效果
--------
silenced:
玩家不能施法。
由 Stupefy 命中触发，持续 1.0 秒。

frozen:
玩家发出的 projectile 速度降低 40%，持续 2.0 秒。
由 Glacius 命中触发。

chilled_global_cd:
Glacius 命中玩家时，把对方全局冷却额外延长 0.5 秒。
这个效果可以积累，但最多只把对方当前全局冷却推到 now + 3.2 秒，避免把对方控到完全放不出技能。

healing:
玩家正在 Lumos 引导回血。
期间被 Incendio / Stupefy 命中会取消回血。

shielded:
玩家拥有 Protego 护盾。
护盾承受伤害，持续时间结束或护盾值归零后消失。


状态机
------
每个玩家单独维护一个施法状态机：

IDLE:
没有明显施法动作，等待玩家进入准备状态。

READY:
检测到手/杖稳定出现，准备记录轨迹。

RECORDING:
记录杖尖轨迹。

CLASSIFY:
轨迹结束，进行咒语分类。

CASTING:
咒语释放成功，生成效果，进入冷却。

COOLDOWN:
等待全局冷却结束，清空轨迹，回到 READY 或 IDLE。


施法判定伪代码
--------------
if player.hp <= 0:
    return

if now < player.global_cooldown_until:
    return

if player.silenced_until > now:
    return

spell, confidence = classify_trajectory(player.trajectory)

if confidence < 0.85:
    clear_trajectory()
    return

if len(player.trajectory) < min_required_frames:
    clear_trajectory()
    return

if now < player.spell_cooldown_until[spell]:
    clear_trajectory()
    return

if player.mana < SPELLS[spell].mana_cost:
    clear_trajectory()
    return

cast_spell(player, spell)
player.mana -= SPELLS[spell].mana_cost
player.global_cooldown_until = now + 2.3
player.spell_cooldown_until[spell] = now + SPELLS[spell].cooldown
player.trajectory.clear()
player.trajectory_consumed = True

当前 CV 接入策略
----------------
第一版 CV 不直接追求最终算法完整度，而是先接通可展示链路：

摄像头 -> MediaPipe Hands -> 食指指尖轨迹 -> 启发式手势分类 -> cast_spell(player_index, spell_name, now)

这样可以先证明“视觉输入可以驱动双人对战系统”。
后续再把食指指尖替换成 HSV + 形态学检测得到的真实魔杖端点，并把启发式分类替换成 DTW 模板匹配。

重要：最终项目不是识别手指，而是识别笔 / 筷子 / 魔杖道具的杖尖。
演示者会手持一支笔或筷子作为魔杖。
MediaPipe Hands 的作用应是辅助定位手、手腕、手心方向和搜索区域；
真正用于咒语分类的轨迹应来自魔杖杖尖坐标。

最终杖尖检测建议：

1. 使用 MediaPipe Hands 找到手腕、手心和手指方向。
2. 在手部外延区域建立 ROI，减少背景干扰。
3. 对 ROI 做 HSV 阈值 / 形态学处理，提取笔或筷子的 mask。
4. 对细长 mask 做 PCA 或轮廓端点检测，找到远离手心的一端作为杖尖。
5. 把杖尖坐标送入现有轨迹分类与 cast_spell 接口。

当前手势映射：

向对方方向快速横向推出: Incendio
向上快速轻挑: Lumos
大 U 形护盾弧: Protego
向下冰冻斩: Glacius
多折返闪电轨迹: Stupefy

CV 灵敏度调参原则：

为了避免手指轻微移动就连续施法，CV 版本要求较大的轨迹幅度。
当前触发需要：

1. 至少约 14 个轨迹点
2. 轨迹总长度至少约 125 px
3. 分类置信度不低于 0.78
4. CV 本地触发锁 1.5 秒
5. 成功施法后仍然受全局冷却和单咒语冷却限制

CV 采样门控：

全局冷却、CV 本地触发锁、沉默、死亡或胜负已定期间，不把手指点加入轨迹缓冲区。
已有轨迹会被清空，屏幕显示 WAIT。
这样释放咒语后的归位动作不会遗留在缓冲区里，也不会在冷却结束后被误判为下一次施法。

识别优先级：

1. Lumos 上挑
2. Incendio 横向前刺
3. Glacius 向下冰冻斩
4. Protego 平滑大弧线
5. Stupefy 多折返闪电

这样可以减少“所有复杂动作都被识别成 Stupefy”的问题。

Protego 不再要求闭合圆：
当前使用大 U 形护盾弧作为护盾手势。
它需要足够宽、足够高、比较平滑，两端高度尽量接近，中间有明显鼓出，并且折返次数少。
普通多折线不应该触发 Protego，而应更倾向 Stupefy。

Glacius 不再使用 Z 字：
Z 字和 Stupefy 的闪电折线过于相似，启发式分类容易混淆。
当前 Glacius 改为从上向下明显划一刀，和 Lumos 的上挑方向相反，区分度更高。

攻击 -> 防御 -> 回血 -> 冷却限制 -> 胜负结算


平衡性原则
----------
1. 攻击不能太便宜，否则护盾和回血没有意义。
2. 护盾不能太频繁，否则游戏拖太久。
3. 回血必须有引导时间，否则残血方很难被击败。
4. 控制技能伤害低，但能改变节奏。
5. Mana 让玩家不能无限施法。
6. 冷却让 CV 识别结果不会被重复消费。
7. 每个咒语都要有克制对象，也要有被克制对象。


一句话总结
----------
Spells 对战系统不是单纯播放特效，而是让视觉识别结果进入一个完整战斗系统：

识别动作 -> 释放咒语 -> 弹道/护盾/回血 -> 碰撞结算 -> HP/Mana/状态变化 -> 胜负结果。
